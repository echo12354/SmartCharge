# 系统架构设计

## 1. 系统定位

SmartCharge 是新能源汽车充电调度与计费管理系统。系统面向充电站运行场景，负责接收用户充电请求、维护等待区与充电区队列、调度可用充电桩、记录充电过程，并在充电结束后生成账单。

当前项目以后端 API 为核心，采用 Flask 提供 HTTP 接口，前端目录作为独立展示层预留。

## 2. 架构目标

- 将接口处理、业务流程、领域状态和通用工具分层组织。
- 保持后端 API 与前端展示解耦，方便后续接入 Web 前端、移动端或接口测试平台。
- 让充电请求、队列调度、充电桩状态、充电会话、账单计费和故障恢复具有清晰边界。
- 便于绘制类图、顺序图和系统事件映射图。
- 支持后续扩展数据库持久化、更多调度策略和更完整的运维统计能力。

## 3. 总体分层

```text
前端或接口测试工具
        |
        v
HTTP API 控制器层
        |
        v
业务服务层
        |
        v
领域模型层
        |
        v
配置、工具与数据访问支持
```

## 4. 目录职责

```text
backend/
|-- app.py
|-- controllers/
|-- services/
|-- models/
|-- database/
|-- config/
`-- utils/
```

### 4.1 `app.py`

Flask 应用入口，负责创建应用实例、注册业务蓝图、开启跨域支持并提供健康检查接口。

### 4.2 `controllers`

控制器层负责处理 HTTP 请求和响应。

主要职责：

- 定义 Flask 路由。
- 解析请求体、查询参数、路径参数和请求头。
- 调用服务层方法。
- 将服务层结果封装为 JSON 响应。
- 避免直接编写复杂业务逻辑。
- 避免直接操作底层数据结构。

典型模块：

- `auth_controller.py`
- `charging_request_controller.py`
- `queue_controller.py`
- `scheduling_controller.py`
- `charging_session_controller.py`
- `bill_controller.py`
- `pile_controller.py`
- `fault_controller.py`
- `compatibility_controller.py`

### 4.3 `services`

服务层是系统业务核心，负责组织系统事件和业务流程。

主要职责：

- 校验业务条件。
- 管理充电请求与等待队列。
- 执行调度策略并维护充电桩队列。
- 创建、更新和结束充电会话。
- 计算并查询账单。
- 处理充电桩故障、恢复和重新调度。

典型服务：

- `UserService`
- `QueueService`
- `SchedulingService`
- `ChargingSessionService`
- `BillingService`
- `PileManagementService`
- `FaultRecoveryService`

### 4.4 `models`

模型层定义业务领域对象，用于表达系统静态结构。

主要职责：

- 保存领域状态。
- 提供简单的状态变更方法。
- 描述用户、请求、队列、充电桩、会话、账单和故障记录之间的关系。

典型模型：

- `User`
- `ChargingRequest`
- `WaitingCar`
- `WaitingQueue`
- `PileQueue`
- `ChargingPile`
- `ChargingSession`
- `Bill`
- `DispatchDecision`
- `FaultRecord`

### 4.5 `database`

数据访问与初始化模块，负责描述数据库状态、初始化入口和后续持久化扩展位置。当前版本主要使用内存状态承载业务运行。

### 4.6 `config`

配置层集中保存系统参数，包括：

- 快充桩与慢充桩编号。
- 充电桩功率。
- 等待区容量。
- 充电桩队列容量。
- 服务费率。
- 峰、平、谷电价。
- 默认用户。

### 4.7 `utils`

通用工具层负责响应封装、参数校验和编号生成等公共能力。

## 5. 核心业务流程

1. 用户登录或注册。
2. 用户提交充电请求，系统生成排队编号。
3. 车辆进入等待区队列。
4. 调度服务根据充电模式、队列顺序和充电桩状态分配车辆。
5. 车辆进入充电桩队列并开始充电。
6. 充电会话记录当前电量、目标电量和运行状态。
7. 充电结束后生成账单。
8. 系统释放充电桩并继续调度下一辆车。

## 6. 故障与恢复流程

当充电桩发生故障时，系统需要：

- 将充电桩标记为故障状态。
- 记录故障信息。
- 找到受影响的车辆和充电会话。
- 中断或转移相关车辆。
- 根据优先级调度或时间顺序调度规则重新安排车辆。

当充电桩恢复时，系统需要：

- 将充电桩恢复为可用状态。
- 更新故障记录。
- 触发等待车辆调度。

## 7. OOD 视角

从面向对象设计角度看，系统可以抽象为：

```text
参与者
-> 控制器对象
-> 服务对象
-> 领域模型对象
-> 数据或状态存储
```

控制器属于边界对象，服务属于控制对象，模型属于实体对象。该划分便于在类图、顺序图和系统事件图中保持一致。
